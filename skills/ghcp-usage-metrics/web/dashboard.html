How these numbers compare to GitHub’s

Every credit shown comes from copilotUsageNanoAiu, the field GitHub itself writes into your local logs. It is not an estimate and not a reconstruction from token prices, so a request that appears here carries the same credit value GitHub recorded for it.

The total can still sit below an official report, and the reason is coverage rather than arithmetic. VS Code rotates its debug logs and trims request bodies out of older sessions; the Copilot CLI only began recording per-request billing in July; Claude Code never reports credits at all. Anything already discarded cannot be counted, and nothing is invented to fill the gap. The authoritative totals live behind GitHub’s billing and metrics APIs, which need organisation-owner or enterprise-admin access — unavailable to an individual account, including an enterprise-managed one.

Treat this as a complete picture of what your machine still remembers, and a floor rather than a bill.

Known limitations of local extraction

  • Claude Code has no AI credits. It records real tokens, but GitHub's AIU metric does not exist there, so its credit total is always 0.
  • Chat-picker agent personas are not recorded. They fold into “GitHub Copilot Chat”. Only subagents launched through runSubagent write their own logs and can be attributed.
  • Skill and agent attribution reaches back less far than requests. VS Code keeps only its most recent sessions in session-store.db; older ones are purged by VS Code, not by this tool.
  • Model, agent and skill breakdowns are lifetime totals. GitHub's per-day telemetry carries no model or agent dimension, so the date range cannot re-scope them.
  • A session that used several skills counts its tokens toward each of them. Per-skill totals therefore overlap and do not sum to the grand total.
  • Debug logs rotate. Older history is reconstructed from trimmed chatSessions, which retain fewer requests per session — so early days look sparse.

Config & hard filters

These exclusions are a hard filter: matching data is removed from the dashboard entirely and disappears from the sidebar — the sidebar checkboxes only narrow whatever is left. Saved in this browser (localStorage), so it survives reloads. Edit the JSON and click Apply, or Download config.json to bake defaults into the Python generator.

Fully honoured (re-scopes every number): since, until (YYYY-MM-DD), exclude.projects (case-insensitive substring), exclude.project_prefixes (starts-with), exclude.clients (vscode / cli / claude).
Breakdown-only: exclude.agents filters the agent panels but cannot re-scope the daily totals, because GitHub's per-day telemetry carries no agent. exclude.models is a hard filter and does re-scope everything, since the logs do record a model per request.
Cost: cost.usdPerAiu (omitted / 0 = every cost figure hidden). GitHub does not publish a machine-readable credit price and none is recorded locally, so costs are only ever your configured rate × recorded credits — a projection, never an invoice.
Auto-refresh: autoRefreshMinutes (0 = off). Inside the VS Code extension this re-scans your logs live on that interval; in a plain browser it reloads the report.
Forecast budget: budget.monthlyAiu (0 / omitted = no budget) drives the Forecast tab's budget comparison; with no budget it shows projected charges only.
Default view: hideEmptyProjects (default true) starts projects that never recorded a token or a credit unticked and tucks them behind a link in the sidebar — they are hidden, never discarded. show.diagnostics (default true) controls whether the Diagnostics tab is offered at all. startAtCreditFloor (default true) opens the view on the first date every harness was reporting AI credits, so a headline never averages complete months together with months that recorded requests only; the earlier data stays selectable.
